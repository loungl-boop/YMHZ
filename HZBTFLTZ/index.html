服务费率实时生效，
结算前必须完成月度确认

将云账户服务费从“补贴明细创建时预写”调整为“生成结算单时实时取值并固化”。费率可随时更新；系统只用月度确认校验防漏，而不以月度费率限制实时变更。

核心决策结算单生成时取最新服务费率；若财务本月未执行过“更新/确认”操作，则拦截生成。已生成单据的费率与金额永不回算。

3. 核心金额口径

逐条计算、逐层汇总

  1. 服务人次服务费 = 该条补贴金额 × 本单服务费率。
  2. 结算对象服务费 = 该对象下服务人次服务费之和。
  3. 结算单服务费 = 全部服务人次服务费之和。
  4. 结算总金额 = 补贴总金额 + 税费总额 + 服务费总额。

舍入口径

服务费按服务人次逐条计算并按既有财务精度保留两位小数，再向上汇总。这样结算单汇总与服务人次、结算对象、打款明细金额完全一致。

示例 补贴 ¥1,000 × 6.70% = 服务费 ¥67.00；税费为 ¥0 时，云账户充值金额 ¥1,067.00。

PRD｜云账户服务费率与补贴结算改造

以“实时生效 + 月度确认拦截 + 多层快照”为核心，减少财务漏更新风险，并保证每笔云账户充值金额可核对、可追溯。

版本范围仅处理云账户服务费率及其在补贴结算中的计算、展示和追溯；税费与打款状态机保持原样。

1. 用户故事

角色用户故事完成标准
财务我希望实时修改或确认云账户服务费率，以便系统使用正确的充值成本。保存后立即生效，产生可查看的历史记录。
财务我希望当月尚未核对费率时得到提醒，避免忘记更新。本月未确认时，配置页有待办提示；结算生成被拦截。
平台管理员我希望生成结算单时系统自动计算服务费，以便财务准确充值。读取最新费率，逐条计算并固化，金额可追溯。
财务/审计我希望看到结算单用了哪次费率更新，以便复核历史金额。结算单详情可查看费率、更新人和更新时间。

2. 功能与交互规则

费率维护

  1. 一个当前费率编辑入口，一个更新历史查看入口。
  2. 保存时记录“调整费率”或“确认费率未变”。
  3. 保存立即生效；不允许覆盖历史记录。
  4. 本月无任何保存记录即视为“未确认”。

生成结算单

  1. 先校验所选明细均为待结算。
  2. 校验本月存在服务费率更新/确认记录。
  3. 锁定当前最新费率记录并计算全部明细。
  4. 税费按现有接口和规则处理。
  5. 创建结算单、明细快照和状态变更须整体成功。

3. 异常处理

场景处理
本月未确认费率禁止生成结算单，提示“本月云账户服务费率尚未确认，请财务先维护费率”。
当前没有可用费率禁止生成结算单，提示维护服务费率。
结算生成时财务同时更新费率本次结算锁定开始生成时读取的费率记录；新费率仅影响后续结算单。
税费查询失败沿用现有异常处理；金额不完整时不得生成结算单。
明细重复入单沿用现有幂等与状态校验，禁止重复结算。
历史费率变更不可修改已保存的历史记录；新保存生成新的记录。

4. 验收清单

  • 财务能够更新或确认本月服务费率，数值未变时也可确认。
  • 当月未确认费率时，生成结算单按钮或提交动作被拦截。
  • 结算单使用生成瞬间的最新费率，不使用补贴明细创建时的费率。
  • 服务人次、结算对象、结算单和打款明细的服务费金额汇总一致。
  • 结算单详情展示本单服务费率及对应历史更新记录。
  • 更新费率不会改变已生成结算单及其关联明细。
  • 税费查询、云账户打款、待确认及已打款状态流转不受本次改造影响。

5. 待研发确认

事项产品口径
金额精度按服务人次逐条计算并保留两位小数，再汇总；以现有财务舍入实现为准。
费率精度配置项支持百分比小数；具体可输入位数与云账户结算精度保持一致。
提醒触达方式配置页待办提示与结算生成拦截为必做；站内信、短信或企业微信提醒按现有通知能力评估。
费率记录标识用于内部关联与审计，不要求在普通列表展示。
