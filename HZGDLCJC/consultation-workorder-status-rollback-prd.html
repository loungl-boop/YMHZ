会诊工单流程纠错 PRD

1. 背景

线上会诊工单已支持病历审核驳回、取消分诊、修改会诊时间、会诊意见审核驳回等标准流转。本次新增能力用于处理标准流程无法覆盖的纠错场景，重点解决“状态已进入下一节点，但业务判断需要回到前一关键处理节点”的问题。

设计原则：

  • 尽量减少跨节点跳转，优先退回至前一个可承接处理的节点。
  • 不允许人工任意选择目标状态，目标状态由系统规则计算。
  • 操作入口展示具体业务动作，降低操作人员理解成本。
  • 所有纠错动作必须留痕，历史数据不物理删除。
  • 复用线上已有能力；待会诊、待上传会诊意见已支持的取消分诊、修改会诊时间不重复建设。

2. 目标

  • 在会诊工单详情页右侧“更多操作”中，根据当前状态、角色权限、数据条件展示具体流程纠错动作。
  • 点击动作后弹出确认弹窗，收集处理原因、必要的数据处理方式和补充说明。
  • 后端完成状态机校验、权限校验、数据处理和变更记录写入。
  • 支持技术同学明确实现：入口展示规则、字段校验规则、状态变更规则、会诊意见处理逻辑、变更记录规则。

待会诊沿用线上修改会诊时间、取消分诊

4. 页面入口

入口位置：会诊工单详情页右侧操作区，点击下箭头展开“更多操作”。

展示规则：

  • 后端返回当前工单可执行动作列表，前端按线上按钮样式渲染。
  • 无可执行动作时，不展示本次新增动作按钮。
  • 同一状态下，如用户角色无权限或数据条件不满足，后端不返回该动作。
  • 按钮文案展示具体动作名称：退回至病历审核、退回至待上传会诊意见、退回至会诊意见审核。

5. 通用交互流程

  1. 用户进入会诊工单详情页。
  2. 点击右侧操作区下箭头，展开更多操作。
  3. 系统展示当前可执行的具体纠错动作。
  4. 用户点击动作。
  5. 系统弹出确认弹窗。
  6. 用户选择处理原因；如为会诊意见阶段退回，还需选择会诊意见处理方式。
  7. 用户可填写补充说明。
  8. 用户点击确认。
  9. 后端校验状态、权限、动作合法性和字段完整性。
  10. 校验通过后，后端完成状态变更、关联数据处理、变更记录写入。
  11. 前端关闭弹窗并刷新工单详情。

6. 弹窗字段规则

字段类型是否必填展示规则说明
工单编号文本是所有动作系统带出，不可编辑
处理动作文本是所有动作系统带出，不可编辑
当前状态文本是所有动作系统带出，不可编辑
处理后状态文本是所有动作系统按规则计算，不可编辑
处理原因下拉单选是所有动作枚举按动作区分
会诊意见处理方式单选条件必填仅会诊意见阶段退回展示可选保留为草稿 / 作废当前意见
补充说明多行文本否所有动作用于记录处理背景、判断依据或沟通结论
影响说明文本列表是所有动作系统展示，不可编辑

校验规则：

  • 处理原因：所有动作必填。
  • 会诊意见处理方式：仅在 待审核会诊意见 / 待复审会诊意见 / 待修改会诊意见 执行 退回至待上传会诊意见 时展示并必填。
  • 补充说明：非必填，不因为空阻断提交。
  • 影响说明：根据动作和会诊意见处理方式动态展示。

7. 动作规则

7.1 待分诊：退回至病历审核

项目规则
当前状态待分诊
动作名称退回至病历审核
处理后状态待审核病历 / 待复审病历
目标状态判断若工单曾因病历补充后重新提交并进入复审链路，则退回至待复审病历；否则退回至待审核病历
适用场景病历审核通过进入待分诊后，发现病历资料仍有问题
后续流程审核人员重新审核；如需补充，由审核人员按现有规则驳回至待用户补充病历或待协助补充病历
数据处理保留原审核通过记录、分诊相关记录和本次退回记录

处理原因枚举：

枚举值说明
病历资料缺失必要病历材料未上传或不完整
病历资料有误病历内容存在明显错误
患者信息不一致病历、订单、患者基础信息不一致
专家反馈病历不完整分诊或会诊准备阶段专家发现病历不足
审核通过有误审核人员误操作通过
其他需在补充说明中描述具体原因，补充说明仍非系统必填

7.2 会诊意见阶段：退回至待上传会诊意见

项目规则
当前状态待审核会诊意见、待复审会诊意见、待修改会诊意见
动作名称退回至待上传会诊意见
处理后状态待上传会诊意见
适用场景会诊未实际开始、需调整会诊时间、需取消分诊，或意见提交时机有误
后续流程工单回到待上传会诊意见后，可继续使用线上已有修改会诊时间、取消分诊，或由专家重新提交意见
数据处理按弹窗选择的会诊意见处理方式执行

处理原因枚举：

枚举值说明
会诊未实际开始会诊室开始触发状态变化，但业务上未形成真实会诊
需调整会诊时间需要重新约定会诊时间
需取消分诊需要回到待上传后再使用线上取消分诊能力
意见提交时机有误专家提前提交或提交时点与实际会诊不一致
其他需在补充说明中描述具体原因，补充说明仍非系统必填

会诊意见处理方式：

选项后端处理逻辑专家后续体验变更记录
保留为草稿将当前有效会诊意见从待审核/复审/修改链路中撤回，保留意见内容为可继续编辑的草稿；原提交、审核、退回历史保留专家再次进入上传意见页面时，可继续基于原内容编辑并重新提交记录“会诊意见处理方式：保留为草稿；意见内容已保留为草稿”
作废当前意见将当前有效会诊意见标记为已作废，不作为后续审核对象；原提交、审核、修改历史保留专家再次进入上传意见页面时，不默认沿用已作废意见作为当前草稿记录“会诊意见处理方式：作废当前意见；意见单已作废”，并记录意见单 ID

实现要求：

  • 保留为草稿 不等于审核驳回，不产生审核驳回结论。
  • 作废当前意见 不物理删除意见单。
  • 两个选项都应使工单状态回到 待上传会诊意见。
  • 后端需保证同一时间只有一份当前有效会诊意见或当前草稿，避免重复提交产生多份有效意见。

7.3 已完成：退回至会诊意见审核

项目规则
当前状态已完成
动作名称退回至会诊意见审核
处理后状态待审核会诊意见 / 待复审会诊意见
目标状态判断若完成前为首次审核通过，则退回至待审核会诊意见；若完成前为修改后复审通过，则退回至待复审会诊意见
适用场景审核误通过、专家要求修改、意见内容有误、质控发现问题
后续流程审核人员重新审核；如需专家修改，由审核人员按现有规则驳回至待修改会诊意见
数据处理保留已完成记录、原意见内容、审核记录和本次退回记录

处理原因枚举：

枚举值说明
审核误通过审核人员误操作通过
专家要求修改专家反馈已完成意见仍需调整
意见内容有误意见存在事实、结论、措辞等错误
意见内容不完整意见缺少必要内容
质控发现问题平台质控或复核发现问题
其他需在补充说明中描述具体原因，补充说明仍非系统必填

8. 后端校验规则

提交时后端必须校验：

校验项规则
状态一致性提交时工单状态必须仍为弹窗打开时的状态
权限当前用户必须拥有该动作权限
动作合法性当前状态、处理动作、处理后状态组合必须在规则配置内
目标状态由后端按历史链路计算，不接收前端任意传入目标状态
处理原因必填，且必须属于当前动作允许的枚举
会诊意见处理方式会诊意见阶段退回时必填，且必须属于允许枚举
作废数据选择作废当前意见时，必须存在可作废的当前有效意见单
事务一致性状态变更、意见处理、变更记录写入必须成功或同时失败

校验失败时：

  • 不执行部分状态变更。
  • 返回明确错误信息。
  • 前端保留弹窗或提示刷新后重试，由实际接口错误码决定。

9. 变更记录规则

每次流程纠错成功后，必须在变更记录中新增一条记录。

基础字段：

字段说明
工单编号当前会诊工单编号
操作人 ID、姓名当前登录用户
操作时间后端服务时间
操作动作具体动作名称
操作前状态提交成功前的工单状态
操作后状态后端最终变更后的工单状态
处理原因弹窗选择的原因
补充说明弹窗填写内容，可为空

会诊意见阶段额外字段：

字段说明
会诊意见处理方式保留为草稿 / 作废当前意见
意见单 ID作废当前意见时记录
数据处理结果意见内容已保留为草稿 / 意见单已作废

展示规则：

  • 查看入口沿用线上 更多操作 > 变更记录。
  • 记录标题使用具体动作名称。
  • 按时间倒序展示。
  • 不覆盖历史记录。

10. 权限建议

本功能属于流程纠错能力，建议仅开放给具备工单运营或管理权限的后台角色。

权限控制建议：

权限点说明
consultation_workorder.rollback_medical_review待分诊退回病历审核
consultation_workorder.rollback_opinion_upload会诊意见阶段退回待上传会诊意见
consultation_workorder.rollback_opinion_review已完成退回会诊意见审核

前端展示以接口返回为准；后端必须独立校验权限。

11. 原型说明

HTML 原型重点展示：

  • 线上风格的会诊工单详情页结构。
  • 右侧下箭头展开更多操作。
  • 当前状态切换后的动作展示差异。
  • 动作确认弹窗字段、校验点和影响说明。
  • 会诊意见处理方式对影响说明和变更记录的联动。
  • 变更记录面板中的新增记录示意。
  • 标注使用可拖拽浮窗展示，便于和页面原型对照查看。
