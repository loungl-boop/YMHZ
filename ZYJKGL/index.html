在尤迈管理后台统一管理中意专家再诊断六个业务节点，完整记录业务处理、定时推送、接口响应和人工处置；当尤迈本地处理失败或向中意反馈失败时，立即通知业务与技术人员。

六个业务节点业务处理可追溯定时任务可观测异常可重试项目与服务可配置企业微信群通知

方案范围

尤迈运营后台

新增对接总览、六个业务节点台账、处理详情、异常处置、接口项目配置、通知设置和对接说明。

异常处置闭环

接收类业务记录尤迈处理结果；推送类业务记录未处理、处理中、反馈成功和反馈失败，并保留每次尝试。

项目与服务路由

创建工单可跨项目集关联多个项目，每个项目选择一个或多个会诊服务，并分别维护项目与服务消耗顺序。

企业微信通知

固定六个业务节点和异常条件，节点仅支持开关；异常消息发送至包含业务、技术人员的固定运营群。

产品结论

以业务节点组织运营台账一个接口可承载多个业务动作，页面按实际业务节点展示，不以物理接口拆分菜单。
业务状态与原始响应分层尤迈运营状态用于判断进度和异常；中意返回的 code/msg/data 原样记录和展示，不新增外部响应枚举。
处理失败与反馈失败统一进入异常中意调用尤迈时关注尤迈是否完成业务处理；尤迈调用中意时关注任务是否执行以及中意是否成功接收。
异常必须通知并可人工处置达到人工介入条件后发送企业微信群消息；业务人员可查看详情，按失败类型重新处理、手动推送或重新推送。

PRD｜中意专家再诊断接口运营管理

版本 1.13 · 一期范围：尤迈运营后台

1. 产品概述

1.1 背景与问题

中意专家再诊断接口已完成对接，正向业务可用。当前尤迈侧缺少面向业务人员和技术人员的运营能力：中意请求到达后，业务处理失败通常只能通过日志发现；尤迈定时推送未执行、响应超时或中意返回失败时，没有统一查询、提醒和人工处置入口；接口使用的项目与服务依赖代码，合同切换及旧项目额度恢复后无法及时调整。

1.2 产品目标

  • 以六个业务节点建立完整台账，记录业务动作、任务调度、接口调用及每次请求响应。
  • 区分正常等待、正在执行、处理成功和需要人工介入的异常，使业务人员无需查询技术日志。
  • 尤迈本地业务处理失败或向中意反馈最终失败时，及时通知固定企业微信群中的业务与技术人员。
  • 允许有权限人员在原记录上查看详情并执行重新处理、手动推送或重新推送。
  • 通过页面配置创建工单可使用的项目、服务及两级消耗顺序，消除代码内项目ID切换。

1.3 一期范围

范围类型内容
本期实现尤迈对接总览、六个业务节点台账、处理详情、人工处置、接口项目与服务配置、企业微信群机器人通知、对接说明、权限及审计。
本期不实现中意查询页面、中意系统改造、新增或修改对外接口协议、独立额度账户、服务适用人群规则、历史工单项目迁移。

1.4 成功标准

  • 六个节点的全部业务记录均可按中意订单号、尤迈工单号及业务条件查询，成功与失败数据均不丢失。
  • 每个应推送业务动作均可追踪计划执行、实际执行、每次调用及最终结果。
  • 需要人工介入的异常在产生后进入总览，并按节点开关发送企业微信群消息。
  • 项目及服务配置变更即时保存，仅影响后续新工单；路由结果可追溯到实际项目ID与服务ID。

2. 用户、场景与权限

角色核心场景权限
业务运营人员发现未处理和异常、核对业务结果、人工补发查看业务及脱敏调用详情；手动推送、重新推送；节点通知开关
技术支持人员定位本地处理、任务调度、HTTP及接口响应问题查看技术明细、追踪号和脱敏报文；受控重试
项目管理员维护创建工单使用的项目、服务与顺序关联、配置服务、拖动排序、启停及移除
审计人员核查人工操作、配置变更和敏感数据访问只读查看操作日志与访问审计

后端必须独立校验数据范围和操作权限；前端按钮隐藏或禁用不能替代后端鉴权。

3. 信息架构与业务节点

  • 对接总览：展示当前未完成总数、未处理、处理中、异常、节点异常分布及当前异常列表。
  • 业务节点：接受并创建工单、尤迈审核结果、预约专家成功、推送诊断结论、中意取消工单、尤迈取消工单。
  • 接口项目配置：跨项目集关联项目，选择项目内会诊服务，并维护项目及服务消耗顺序。
  • 通知设置：展示固定通知渠道、接收范围、机器人状态、六个固定节点条件及开关。
  • 对接说明：展示业务与接口映射、当前未调用状态及现行接口文档链接。
节点方向触发与业务口径接口请求/响应成功判定

接口文档定义的 status=1“审核不通过”、status=4“预约失败”、status=5“更新专家信息”当前没有独立业务触发，不提供构造或手动调用入口；仅在“对接说明”标记暂无调用。更换专家继续使用预约成功 status=3。status=9 按当前已上线代码解释为取消会诊/取消工单。

4. 任务状态、异常与人工处置

4.1 推送类任务状态

状态定义进入条件允许操作
未处理业务结果已产生并已生成任务，尚未到计划执行时间当前时间小于等于计划执行时间，且没有开始记录查看详情、手动推送
处理中定时任务或人工操作已领取，正在组装、发送或等待响应存在开始时间且未产生终态，并未超过处理超时阈值仅查看详情
反馈成功已取得可解析的中意响应且 code=0最近一次有效调用返回 code=0查看详情
反馈失败任务未按时执行，或调用未取得成功响应超过计划执行时间及宽限仍未开始；HTTP/网络/超时/格式异常；中意返回 code=1/2；且自动重试结束仍未恢复查看详情、手动推送或重新推送

4.2 接收类处理状态

状态定义允许操作
处理中尤迈已经接收请求，业务事务尚未结束仅查看详情
处理成功工单创建或取消事务完成，并返回 code=0查看详情
处理失败项目/服务路由、工单创建、工单取消或系统重新处理失败查看详情、重新处理

4.3 统计口径

  • 当前未完成总数 = 未处理 + 处理中 + 异常；异常 = 当前反馈失败 + 当前接收处理失败。
  • 同一业务动作只按最新状态计入一个统计分类；每次自动调用、自动重试和人工调用均保留历史，不重复计入当前指标。
  • 总览只展示当前未完成及异常；六个业务节点页面展示该节点全部状态和全部业务记录。
  • 当前指标和列表按页面本次刷新时的尤迈服务端时间计算，数字支持下钻到相应标签。

4.4 人工操作

  • 未处理显示“手动推送”；处理中不提供发起操作；反馈失败根据原因显示“手动推送”或“重新推送”。
  • 接收处理失败显示“重新处理”。提交时后端使用业务动作唯一键加锁并复核最新状态，避免重复执行。
  • 操作完成后保留当前页面、筛选条件、标签与滚动位置，刷新该记录及指标；所有人工操作写入审计日志。

5. 页面功能要求

5.1 对接总览

  • 指标固定展示当前未完成总数、未处理、处理中、异常；点击数字进入二级明细页并支持四个标签切换。
  • 节点异常卡片只统计反馈失败和接收处理失败；点击数字进入该节点并预置异常筛选。
  • 当前异常列表按最近异常时间倒序，不按业务流程排序；列表操作直接对应当前失败原因，并同时提供查看详情。
  • 页面右上角提供刷新按钮；刷新成功更新统计时间与数据，失败保留原数据并提示。

5.2 业务节点列表

六个节点使用统一筛选框架：订单/工单号、关联项目、业务结果、处理状态、响应结果、开始日期、结束日期；其中仅适用于当前节点的业务结果选项不同。查询条件之间使用 AND；日期为闭区间且开始日期不得晚于结束日期。默认按最近业务时间倒序。

列表固定展示中意订单号、尤迈工单号、关联项目、业务结果/操作、当前状态、最近响应、累计尝试次数、最近时间和操作。不存在的尤迈工单号或关联项目显示“—”，不得以空字符串或 0 代替。

5.3 统一处理详情

  • 所有节点共用相同结构：业务信息、处理汇总、逐次调用/处理记录、所选单次请求数据、所选单次响应数据。
  • 公共业务信息：节点、中意订单号、尤迈工单号、关联项目、所属项目集、实际服务、业务结果/操作。
  • 处理汇总：当前状态、状态说明、计划执行时间、实际开始时间、完成时间、累计尝试次数、最近响应、失败原因、下次重试时间。
  • 逐次记录：次数、触发方式、执行人/任务、开始时间、结束时间、耗时、HTTP状态、code、msg、结果；点击记录切换下方报文。
  • 请求和响应以不可编辑格式化 JSON 展示；敏感字段按统一脱敏规则处理；无响应时展示失败阶段与技术错误，不伪造 code。

6. 接口项目与服务配置

6.1 候选数据与筛选

  • 候选项目读取当前账号可见的全部项目状态，不预设状态过滤；未开始、进行中、已归档均返回。
  • 已归档、已关联或不存在可用会诊服务的项目保留展示但不可选择；未开始项目允许提前关联。
  • 项目名称/项目ID为包含匹配；项目集和项目状态均为多选，未勾选时分别显示“全部项目集”“全部状态”。不同筛选项使用 AND，同一多选项内部使用 OR。
  • 候选服务只读取该项目当前配置且产品类型为“会诊”的服务；项目可选择一个或多个服务。不处理服务适用人群。

6.2 字段与顺序

字段来源与规则
项目/项目ID项目主数据；ID作为配置关系唯一键，名称只用于展示。
所属项目集项目当前所属项目集名称；支持跨项目集同时关联。
项目状态项目主数据当前状态；一期展示未开始、进行中、已归档。
项目周期项目开始日期至结束日期；创建工单时实时复核。
服务及服务ID项目—服务关系中的会诊类服务；服务ID作为配置唯一键。
已用/总量按当前项目、当前已选服务分别实时计算；仅计入该服务的有效工单，不保存独立余额。
项目顺序主列表拖动行调整，落位即保存；序号按保存结果重新连续编号。
服务顺序服务配置弹窗拖动已选服务调整，提交后保存该项目的有序服务ID列表。

6.3 创建工单路由

  1. 按启用项目顺序逐个读取项目。
  2. 实时校验项目状态、周期及项目有效性；不可用则继续下一项目。
  3. 按该项目已选服务顺序实时校验服务状态、项目—服务关系和剩余可用量；不可用则继续下一服务。
  4. 命中首个可用服务后，在同一事务内占用数量并创建工单，保存项目ID、服务ID与当时名称快照。
  5. 全部项目与服务均不可用时，创建失败、向中意返回接口文档定义的失败响应、进入异常并触发通知。

配置的关联、拖动排序、启停与移除均即时保存，只影响保存后创建的新工单。保存失败时页面恢复后端已保存顺序，并提示失败；不得只在前端改变顺序。

7. 企业微信群机器人通知

7.1 渠道与页面配置

  • 一期固定使用一个企业微信群机器人，群内包含业务人员和技术人员；页面不配置收件人、阈值、重试次数或消息模板。
  • 页面固定展示通知方式、固定通知群、接收对象、机器人状态、最近检测时间、六个节点的固定条件、最近通知及节点开关。
  • 节点开关即时保存。关闭仅阻止后续新异常通知，不关闭异常记录、不取消重试、不影响其他节点。
  • 机器人 Webhook 仅在后端密钥配置中保存和使用，页面不展示完整地址；机器人检测成功以企业微信返回 errcode=0 为准。

7.2 发送格式与限制

规则一期要求
消息类型使用企业微信群机器人 markdown 消息。
内容长度UTF-8 编码不超过 4096 字节；生成后必须校验，超长时优先截断失败原因并保留详情链接。
格式能力仅使用标题、加粗、引用、行内代码、链接及 info/comment/warning 字体颜色；不得使用客户端不支持的任意 HTML。
频率限制同一机器人不超过 20 条/分钟；超过时进入先进先出发送队列，不丢弃异常消息。
隐私禁止发送患者姓名、证件号、手机号、疾病描述、诊断结论正文、附件、完整请求响应、签名、密钥或 Webhook。

7.5 发送、去重与失败处理

  • 通知唯一键为“业务动作ID + 业务节点 + 异常阶段”。同一异常阶段只发送一次；异常恢复后再次进入新的异常阶段可重新发送。
  • 消息发送成功以企业微信返回 errcode=0 为准；保存请求摘要、响应、发送时间、次数和结果。
  • 机器人调用失败后按 1、5、15 分钟重试，共3次；仍失败则记录通知失败并写入技术监控日志，不递归使用同一机器人发送自身失败告警。
  • 业务异常通知不能替代异常台账。通知发送失败不改变原业务动作的处理/反馈状态。

8. 数据模型、接口与非功能要求

8.1 核心实体

实体关键内容
业务动作actionId、节点、orderId、workOrderNo、业务结果、项目/服务快照、当前状态、计划/开始/完成时间
执行尝试attemptId、actionId、序号、触发方式、执行人/任务、起止时间、HTTP状态、code/msg、错误类型、脱敏请求响应
项目服务路由对接方、业务节点、有序项目ID、项目启停、有序服务ID、版本、操作审计
通知记录通知唯一键、节点、消息摘要、发送次数、企业微信响应、发送状态、发送时间

8.2 幂等与并发

  • 接收接口按中意订单号和接口文档幂等键防止重复建单或重复取消；重复请求返回文档允许的既有结果。
  • 推送任务按业务动作ID唯一；人工操作和定时任务竞争时只允许一个执行者领取，其他请求返回“任务已处理中”。
  • 每次尝试新增不可变记录，禁止覆盖旧请求响应；当前状态由最近有效尝试聚合。

8.3 安全、审计与性能

  • 日志和页面按字段级规则脱敏；原始密钥、签名、Webhook、医疗敏感正文不得进入普通业务页面或企业微信群。
  • 配置、人工处置、通知开关、敏感详情查看全部记录操作人、时间、对象、修改前后值、IP和结果。
  • 列表查询目标响应时间 P95 ≤ 2 秒；详情 P95 ≤ 3 秒。大报文采用按需加载，列表不读取完整请求响应。
  • 业务动作、执行尝试、通知记录保留期遵循尤迈现行合规留存政策；删除或归档不能破坏审计链。

9. 验收标准

  1. 总览四项指标可按规则下钻，二级页支持标签切换、刷新和原地处置；统计与列表在同一快照口径下相符。
  2. 六个业务节点页面能查询并展示该节点全部状态数据，默认按最近业务时间倒序。
  3. 统一详情完整展示公共业务信息、九项处理汇总字段、全部执行尝试及所选尝试的脱敏请求响应。
  4. 未处理可手动推送、处理中无发起操作、反馈失败可重新推送、接收处理失败可重新处理；并发重复提交被后端阻止。
  5. 项目候选支持项目集和状态多选；已归档不可选；项目与服务均可拖动排序且保存后刷新顺序不丢失。
  6. 创建工单按项目顺序、服务顺序及实时可用性命中；无可用项目/服务时返回既有失败结果、进入异常并触发通知。
  7. 六个节点开关即时保存；开启节点产生需人工介入异常时，机器人消息内容、长度、限流、脱敏、去重和发送记录符合第7章。
  8. 机器人关闭、不可用或发送失败不影响业务台账及人工处置，通知通道重试结果可审计。
  9. 中意查询入口、页面、权限和相关文案不出现在一期交付物中。
