统一术语与展示名称

统一名称定义禁止混用
当前有效发布版本所选日期生效且当前未被后续发布或撤回替代的排班发布快照。不写“当前排班”“有效草稿”。
资源可用班次班次的资源状态为可用，可参与工单承接和容量计算。不写“可工作状态”“可分配班次”。
资源不可用班次班次的资源状态为不可用，仅展示，不参与容量。不单独写“休息功能”；“休息”只是模板名称示例。
已确认护士工单工单原始护士ID非空；页面按该护士显示。统计说明可写“已分配护士单数”，但不写“已确认工单”。
未分配护士工单工单原始护士ID为空；进入模拟占位计算。不写“未确认工单”作为页面展示名称。
模拟占位工单未分配护士工单已按规则找到临时展示护士；仅影响看板容量，不回写工单。不写“模拟测算”“预分配工单”。
无可用护士工单未分配护士工单无法找到完整可承接护士，进入独立轨道且不扣减容量。不写“溢出工单”；overflow仅可作为技术枚举。
安排异常工单已确认护士工单未完整落入资源可用班次，或与同护士其他已确认护士工单重叠。不自动改派，不归入无可用护士工单。
剩余资源容量某连续时段内仍可完整承接工作的去重护士人数。不写“剩余工位”“剩余班次数”。

背景、问题与目标

业务现状
  • 当前团队护士长1人，护士不足10人。
  • 排班已发布，但相关服务人员无法在安排服务时直观看到护士占用。
  • 护士不能同时承接多项工作，服务开始时间需要结合当日资源调配。
一期目标
  • 让有权限人员快速判断任意时段剩余可承接护士人数。
  • 统一展示已确认护士工单、模拟占位工单和无可用护士工单。
  • 安排异常可见、可追溯，但不在看板内修改业务数据。

成功标准

当日范围内的有效班次与符合业务状态的工单均可被展示或归入明确异常；相同输入产生相同的模拟分配结果；页面不得返回或展示患者姓名、联系方式、诊断和病历内容。

用户、入口与权限

相关服务人员

查看护士整体资源容量、工单占用和无可用时段，不关心具体应指派哪名护士；可在具备既有按钮权限时进入工单详情。

护士长

查看已发布排班与实际工单安排是否存在冲突，识别需要协调的服务时间；看板只读，排班维护仍在“护士排班”。

菜单层级：“护士资源看板”与“护士排班”同级。系统已有菜单、按钮级权限配置，本期开发只新增权限资源，不硬编码角色；权限分配由管理员或运营人员完成。

核心业务口径

主题一期规则页面结果
护士范围读取账号体系中角色为“护士”的全部账号；是否参与本月排班不影响名单展示。未排班护士显示“当日未排班”，不计入容量。
排班版本仅取所选日期当前有效的已发布版本；草稿、已撤回版本不参与。版本及发布时间显示于看板顶部。
可用资源仅班次模板标记为“资源可用”的实际班次区间参与计算。可用/不可用班次采用不同底色。
已确认护士工单工单护士ID非空；按该护士实际展示。即使冲突或不在可用班次内，也不改派。安排异常卡片标红并计入异常。
未分配护士工单工单护士ID为空；按开始时间、创建时间、工单号顺序模拟占位。成功时显示模拟占位工单；不回写工单护士ID。
可承接条件工单完整预计区间必须落在同一连续资源可用班次内，且与已占用区间完全无重叠。无候选护士时进入“无可用护士”轨道。
剩余资源容量资源可用护士数减去该时段被已确认护士工单或模拟占位工单占用的去重护士数。按班次/工单开始结束等资源变化点分段，相邻同值合并。

刷新与失败保护

每60秒自动刷新，手动刷新不遮挡页面；更新期间继续显示旧数据。单次请求10秒超时，失败后保留最后成功数据并展示更新时间，避免弱网卡死。

空态

  • 无有效发布版本：不计算容量或模拟占位，并列出符合范围的工单审计信息。
  • 当日无符合状态工单：保留班次和完整容量，仅显示说明条。
  • 护士未排班：保留护士行，显示“当日未排班”。
  • 首次加载失败且无成功数据：展示错误态和重新加载按钮。

1. Executive Summary

1.1 Problem Statement

相关服务人员在安排服务开始时间时，无法把已发布排班和当日工单占用放在同一时间轴判断，容易高估护士资源；护士不能同时承接多项工作，因此需要统一、可解释的剩余容量视图。

1.2 Proposed Solution

新增与“护士排班”同级的只读“护士资源看板”，以所选日期的当前有效发布版本为资源基线，聚合现有工单，服务端完成异常校验、模拟占位和容量分段，前端按分钟展示00:00–24:00。

1.3 Success Criteria

指标验收标准
数据完整性与所选自然日有时间交集且状态符合范围的工单，100%归入已确认护士工单、模拟占位工单或无可用护士工单；角色为“护士”的账号100%展示。
算法确定性相同排班、工单、护士顺序和算法版本重复计算结果完全一致；任何正时长交集均判为重叠，边界相接不算重叠。
隐私看板聚合接口、页面DOM和看板日志均不包含患者姓名、联系方式、诊断、病历。
可用性刷新不阻断浏览；10秒超时保留最后成功数据；首次无成功数据时提供重新加载。
性能护士≤20、所选日相关工单≤500时，聚合接口P95≤2秒，页面首次可交互P95≤3秒。

1.4 Dependencies

  • 账号体系及现有菜单、按钮权限配置。
  • 护士排班当前有效发布版本、护士和实际班次。
  • 现有产品、服务、工单、预计时间及业务流程状态。

2. User Experience & Functionality

2.1 User Personas

相关服务人员

主要查看某个时间段是否仍有护士可承接，不以确定具体护士为目标。

护士长

查看已确认护士工单是否与班次或其他工单冲突，并进行线下协调。

2.2 User Stories

  • 作为相关服务人员，我希望按日查看各时段剩余资源容量，以便调整服务开始时间。
  • 作为相关服务人员，我希望未分配护士工单先模拟占位，以免高估资源。
  • 作为护士长，我希望看到已确认护士工单的冲突或越界安排，以便协调。
  • 作为有详情权限的用户，我希望从卡片查看缩略信息并进入现有工单详情。

2.3 Acceptance Criteria

ID完成定义
AC-01 权限有菜单权限可进入；无权限前端不显示入口且接口返回403；详情按钮继续使用既有按钮权限。
AC-02 日期默认今天；今天定位当前时间，其他日期定位06:00；时间轴固定00:00–24:00并可横向滚动。
AC-03 数据使用当前有效发布版本；全部护士均展示；未排班护士显示“当日未排班”且不计入容量。
AC-04 分配已确认护士工单不改派；未分配护士工单按确定性顺序模拟；完整区间未被同一资源可用班次包含或存在重叠时不得分配。
AC-05 显示班次、工单均按分钟定位；15分钟格不取整；同轨道重叠卡片分层且可点击，不相互遮盖。
AC-06 容量按变化点分段；相邻同值合并；点击分段可查看构成；不展示空闲护士姓名。
AC-07 状态完整支持正常、刷新失败保留旧数据、无工单、无有效发布版本、首次加载失败五种页面场景。
AC-08 工单点击工单打开缩略弹窗；仅有既有权限时显示详情按钮；看板接口和缩略弹窗无患者敏感字段。

区域统一展示名称与行为

2.6 Empty & Boundary States

  • 无工单：继续展示排班和容量，概览相关指标为0。
  • 无有效发布版本：不计算容量或模拟占位，保留工单审计列表。
  • 未排班护士：保留护士行，不计入容量。
  • 跨日班次/工单：页面裁切显示，完整区间参与包含与冲突判断。
  • 边界相接：A.end_at = B.start_at 时不算重叠。

2.7 Non-Goals

一期不支持派单/改派、筛选、周月视图、修改排班、资源预约、实际服务时间、消息推送、患者信息展示或新增产品服务配置。

3. AI System Requirements

不适用。本期不使用生成式AI、机器学习或概率推荐；模拟占位为可解释、确定性的规则算法，相同输入必须产生相同输出并可由算法版本和聚合日志还原。

4.2 Integration Points & Permissions

资源权限码/来源开发规则
菜单nurse_resource_board:view开发注册到现有菜单权限体系；前端按配置显示，聚合接口校验同一权限；不绑定固定角色。
查看工单详情按钮复用各产品现有详情权限前端无权限隐藏按钮；后端详情接口继续独立鉴权。
护士现有账号/角色数据返回角色为“护士”的全部账号；按账号体系稳定显示顺序，其次按nurse_id升序。
排班当前有效发布版本只读发布快照；草稿、已撤回和非当前版本不得进入计算。
产品/服务/工单现有业务数据复用现有产品流程和服务配置，不新增对应关系维护。

4.3 Data Flow & Calculation Ownership

  1. 服务端校验日期和菜单权限，生成请求ID。
  2. 按半开区间[day_start, day_end)读取与所选自然日有交集的当前发布班次和工单；跨日数据必须带原始起止时间。
  3. 过滤四类产品及对应状态，规范空白护士ID为null。
  4. 服务端完成已确认护士校验、未分配护士工单模拟占位、容量分段和异常归类。
  5. 服务端返回统一只读视图模型；前端只裁切所选日、计算像素位置和渲染。
  6. 点击详情复用各产品现有详情路由和后端鉴权。

4.4 Query API

GET /api/nurse-resource-board?date=YYYY-MM-DD；不分页，一次返回所选日完整视图；请求与响应Content-Type为application/json; charset=utf-8。

请求字段必填规则错误提示
date是字符串；ISO日期YYYY-MM-DD；必须为Asia/Shanghai下的有效自然日；一期不限制历史/未来范围。400：查看日期格式不正确

4.5 Response Model

对象.字段类型/必填规则
request_idstring/是1–64字符；单次请求唯一，用于前后端日志关联。
algorithm_versionstring/是1–20字符；规则变更必须升级版本并保留兼容说明。
updated_atdatetime/是ISO 8601且包含+08:00；本次聚合完成时间，刷新失败时前端保留上次值。
publication.statusenum/是effective当前有效；none无有效发布版本。none时版本字段为空。
publication.version_idstring/条件必填1–64字符；effective时必填。
publication.version_namestring/条件必填1–30字符；effective时必填，仅展示。
publication.published_atdatetime/条件必填ISO 8601且包含时区；effective时必填。
summary.*integer/是返回scheduled_nurse_count、available_minutes、order_count、confirmed_order_count、simulated_order_count、overflow_order_count、abnormal_order_count；均≥0。
nurses[].nurse_idstring/是1–64字符；账号体系唯一ID；同一响应内唯一。
nurses[].display_namestring/是1–50字符；不得返回工号；前端超出列宽省略并通过title展示原值。
nurses[].avatar_textstring/是1–2个中文字符；优先取姓名末2字，不足则全名。
nurses[].sort_indexinteger/是≥0；账号体系稳定顺序；相同则按nurse_id升序。
nurses[].scheduledboolean/是是否存在与所选自然日相交的班次；false仍返回护士行。
shifts[].shift_idstring/是1–64字符；发布快照内唯一。
shifts[].nurse_idstring/是必须引用nurses中的护士。
shifts[].namestring/是1–20字符；取发布快照值。
shifts[].start_at/end_atdatetime/是ISO 8601且end_at晚于start_at；允许跨日，返回原始完整区间。
shifts[].resource_availableboolean/是true为资源可用班次，参与容量；false为资源不可用班次，仅展示且不参与容量。
orders[].order_idstring/是1–64字符；现有工单唯一ID；同一响应内唯一。
orders[].product_typeenum/是consult会诊、clinic诊所服务、remote远程门诊、green绿通。
orders[].service_namestring/是1–50字符；取现有服务展示名称；卡片溢出省略，弹窗显示完整值。
orders[].workflow_statusstring/是必须属于对应产品纳入状态枚举。
orders[].expected_start_atdatetime/是ISO 8601且包含时区；一期占用开始时间。
orders[].expected_duration_minutesinteger/是正整数；当前来源数据最短10分钟；不按15分钟取整。
orders[].created_atdatetime/是ISO 8601且包含时区；用于模拟占位第二排序键。
orders[].source_nurse_idstring/null/是工单原护士ID；空字符串先规范为null；非空表示已确认护士，null表示未分配护士。
orders[].display_nurse_idstring/null/是确认护士或模拟护士；无可用护士时为null。
orders[].allocation_typeenum/是confirmed已确认护士、simulated模拟占位、overflow无可用护士。
orders[].abnormalboolean/是仅confirmed可能为true；simulated和overflow固定false。
orders[].reason_codeenum/null/是outside_available_shift未完整落入可用班次、confirmed_overlap确认安排重叠、no_covering_shift无人完整覆盖、all_candidates_busy候选均冲突；正常时null。
capacity_segments[].start_at/end_atdatetime/是连续、无交叠并覆盖所选自然日；相邻同人数段必须合并。
capacity_segments[].remaining_countinteger/是≥0；可承接护士去重计数。

4.7 Deterministic Simulation Algorithm

  1. 先装载全部已确认护士工单；无论是否安排异常，均占用原护士时间且不自动改派。
  2. 未分配护士工单按预计开始时间升序、创建时间升序、工单号字典序依次处理。
  3. 候选护士必须存在一个连续资源可用班次完整包含工单区间，且与已确认护士工单及此前模拟占位工单完全无重叠。
  4. 候选排序：包含该工单的空闲窗口结束时间最早者优先；相同则按护士稳定显示顺序，再按护士ID升序。
  5. 有候选则生成simulated并参与后续容量；无候选生成overflow和原因。两者均不写回工单。

4.8 Capacity Algorithm

变化点集合=自然日边界+资源可用班次开始/结束+已确认护士工单及模拟占位工单开始/结束。每个相邻区间计算“存在资源可用班次的护士集合 − 被工单占用的护士集合”的差集人数；同一护士多条重叠工单只扣减1人，相邻同值区间合并。安排异常工单仍按原护士占用，但剩余容量不得小于0。

4.9 Errors & Invalid Source Data

情形接口/页面处理
400日期非法；页面保留原日期并提示“查看日期格式不正确”。
401进入现有登录失效流程。
403展示现有无权限页；不得返回看板业务数据。
200 + publication.none展示无有效发布版本空态，不作为接口错误。
5xx/网络失败，已有成功数据保留最后成功数据和更新时间，显示顶部警示和失败Toast。
5xx/网络失败，无成功数据展示首次加载失败空态及“重新加载”。
前端10秒未收到结果取消本次视图更新，保留旧数据；迟到响应不得覆盖更新结果。
工单缺少预计开始或时长≤0不进入容量计算；服务端记录invalid_order_time告警并计数，不向前端返回该工单。
未知产品或状态不在枚举按“不在展示范围”排除并记录统计，不作为页面错误。
已确认护士ID不在当前护士名单视为数据完整性错误，聚合接口返回5xx；已有成功数据时前端保留旧数据，无成功数据时展示首次加载失败空态。
重复工单ID聚合失败并记录数据完整性错误，不允许前端自行去重。

4.10 Security, Privacy & Non-Functional Requirements

  • 安全：聚合接口使用字段白名单；菜单和详情接口均服务端鉴权；所有页面输出先HTML转义。
  • 隐私：看板及缩略弹窗只返回工单号、产品、服务、状态、预计时间、护士资源结果和创建时间。
  • 一致性：单次聚合使用同一逻辑快照；响应带request_id、updated_at和algorithm_version。
  • 可访问性：按钮可键盘聚焦；弹窗使用dialog语义、Esc关闭；状态同时使用文字、颜色和线型。
  • 兼容性：一期PC端，遵循项目现行浏览器基线；宽度不足时横向滚动，不压缩时间精度。
  • 可观测性：记录耗时、发布版本ID、护士数、班次数、工单数、模拟数、overflow数、异常数、排除数和失败原因；不得记录患者敏感字段。

5. Risks & Roadmap

风险影响控制措施
预计时间不准确容量与实际占用存在偏差一期明确标注预计口径；后续接入实际时间。
发布排班与工单更新非同一事务瞬时结果不一致响应返回统一updated_at和版本；60秒刷新；服务端单次快照聚合。
已确认护士工单本身冲突容量可能被高估或现场撞单保留原安排并显著标红；计入占用与异常，不自动修正。
跨日边界只看当日切片可能误判展示裁切、校验用完整区间；纳入相邻日跨界数据。
权限只在前端隐藏数据越权菜单与详情接口均服务端鉴权。

5.1 里程碑

  1. 一期：只读日看板、预计时间、轮询刷新、规则模拟、异常及空态。
  2. 后续1：接入实际开始/结束时间并区分预计/实际占用。
  3. 后续2：临近可用时段建议、实时推送和调度优化；需另立项评审。

5.2 验收清单

  • 使用固定数据集校验排序、完整包含、边界相接、多任务重叠、跨日、未排班、无发布、无工单和刷新失败。
  • 核对四类产品全部状态枚举，确认没有额外状态进入看板。
  • 验证无菜单权限、无详情权限和接口直调三种鉴权场景。
  • 检查接口响应、页面DOM、错误日志中均无患者敏感字段。
