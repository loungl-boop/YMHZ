01　评审结论

本方案不改变产品、服务、合同、项目集、项目、工单的既有业务关系，只补齐可继承、可覆盖、可在单据内调整的预计服务时长。

交付内容服务的“默认预计服务时长”、项目集服务及工单的“预计服务时长”三处配置与展示
不纳入范围合同维度时长、人员排班占用预览、报告解读与就医指导工单
影响端仅服务平台管理后台；患者端、专家端本期均不新增展示
新增字段服务默认值、项目集覆盖值、工单快照值，统一存储分钟
状态与流程不新增状态；分别嵌入现有创建、分诊、协调结果流程
权限策略沿用对应服务、项目集与工单现有查看/编辑权限
历史数据远程门诊沿用已有“服务时长”；其他存量记录不强制回填
兼容策略配置只影响后续新建工单，不批量修改历史工单快照

02　背景与目标

解决的问题当前服务数量只能表达“要完成多少单”，不能表达“每单需要占用多久”，导致项目执行量无法换算为人员工作量，排班预览也缺少可靠的时长输入。

业务目标

  • 为每张具有明确服务时间的工单形成稳定的预计服务时长。
  • 允许相同服务在不同项目集执行时采用不同的时长要求。
  • 保持配置复用：大多数场景直接继承服务默认值，仅项目集有差异时覆盖。
  • 为后续“工单时长 × 参与角色 × 排班时间”计算人员占用提供基础数据。

业务结构保持不变

产品定义工单流程
→
服务销售商品与默认时长
→
项目集执行要求与时长覆盖
→
工单本次预计时长快照

合同继续负责服务项、数量和价格；项目继续负责数量分配与最小执行管理。本次不在合同或项目维度重复维护时长。

04　核心业务规则

统一分钟口径界面与数据均只保留分钟，不提供小时单位切换；输入 120 即表示 120 分钟。
配置与展示分离服务属性配置页只维护默认值，不在字段“展示预览”中显示，避免被误解为患者填写字段。
项目集双入口一致无论服务来自关联合同还是手动分配，都展示预计服务时长并提供“配置时长”操作。
快照不追溯服务或项目集配置变化，只影响变化后创建的工单；已创建工单保持原值。
按业务时机录入诊所/远程门诊在创建时录入，会诊在分诊时录入，绿通在安排协调结果时录入。
沿用现有权限不新增独立权限点，是否可改时长与当前页面已有配置或修改操作权限保持一致。
来源可追溯工单保存时同时记录来源：服务默认、项目集覆盖或工单调整。
其他端不展示预计服务时长用于服务平台内部资源评估，患者端、专家端本期均不新增展示，也不作为对患者承诺的实际服务时长。

05　范围与边界

交付范围

  • 所有产品类型的服务配置增加默认预计服务时长。
  • 项目集服务列表支持展示、继承和覆盖时长。
  • 会诊、诊所服务、远程门诊、绿通工单保存时长快照。
  • 四类工单在现有业务入口中支持查看和修改。
  • 远程门诊原“服务时长”数据迁移并统一字段名称。

不纳入范围

  • 合同维度、项目维度重复配置服务时长。
  • 排班占用预览、人员冲突校验和自动排班。
  • 报告解读、就医指导原型与工单适配。
  • 购药、健康报告、电话咨询、慢病管理等暂无明确服务时间的工单。
  • 实际服务时长、计费时长、绩效核算时长。

  • 远程门诊已有“服务时长”字段：沿用原字段数据，统一接口语义、页面名称和分钟口径，避免重复建字段。

01　概要说明

问题陈述

现有合同、项目集和项目只能管理服务数量，工单没有统一的预计时长快照，无法可靠换算角色占用，也无法为人员排班预览提供标准输入。

解决方案

在服务、项目集服务、工单三个层级建立分钟制预计时长：服务提供默认值，项目集按执行要求选择继承或覆盖，工单按业务时机带入并允许本单调整。

成功标准

  • 适用范围内新建工单的预计服务时长保存完整率为 100%。
  • 工单取值与“工单调整 ＞ 项目集覆盖 ＞ 服务默认”规则一致率为 100%。
  • 配置变更不得修改任何已创建工单快照，回归通过率为 100%。
  • 远程门诊迁移前后已有服务时长值一致，数据差异为 0。
  • 四类工单的创建、编辑、查看入口均能展示相同分钟值。

术语定义

术语定义
默认预计服务时长服务层面的通用基础值。
项目集覆盖值相同服务在特定项目集中的差异化执行时长。
工单预计服务时长当前工单最终使用的时长快照，不等于实际服务时长或计费时长。
适用工单当前版本中具有明确服务日期与时间的会诊、诊所服务、远程门诊、绿通工单。

02　用户体验与用户故事

用户角色

产品/服务运营维护默认预计服务时长，保证基础配置可复用。
项目经理按项目集执行要求继承或覆盖服务时长。
工单操作人在创建、分诊或协调时确认本次服务时长。
资源管理人员后续基于工单时长评估角色占用和排班。

用户故事与完成定义

用户故事完成定义
作为服务运营，我希望为服务配置默认预计时长，以便新项目直接复用。可输入分钟整数；快捷值可点击；保存后项目集与新建工单可读取。
作为项目经理，我希望相同服务在不同项目集使用不同预计时长，以便表达实际执行要求。关联合同与手动分配两类服务均可配置；默认继承；覆盖后列表展示覆盖值和来源。
作为工单操作人，我希望在实际安排服务时调整预计时长，以便本单更符合实际。四类工单在各自业务入口可修改；保存后详情显示最终值与来源。
作为资源管理人员，我希望每张适用工单都有稳定时长快照，以便后续计算角色占用。配置变化不追溯历史；接口可返回分钟值与来源。

非目标

不实现人员排班、冲突检测、实际时长采集、按分钟计费、合同级时长、项目级时长，也不向患者端展示预计服务时长。

03　功能需求

FR-01　默认预计服务时长

  • 入口：产品服务 → 服务 → 属性配置。
  • 所有产品类型的服务均增加“默认预计服务时长”。
  • 字段为必填正整数，单位固定为分钟，允许范围 5—1440。
  • 提供 10、15、20、30、60、120 分钟快捷按钮；点击后写入输入框。
  • 字段属于系统设置，不进入“展示预览”，不展示给患者或申请人。
  • 远程门诊已有“服务时长”沿用原数据，仅统一名称与分钟口径。

FR-02　项目集服务继承与覆盖

  • 入口：项目中心 → 项目管理 → 项目集详情。
  • 项目集通过“关联合同”或“手动分配”获得的服务，均在服务列表增加“预计服务时长”和“配置时长”。
  • 新增项目集服务时默认继承服务默认值；列表标记“继承服务”。
  • 选择“自定义本项目集预计时长”后必须输入 5—1440 的分钟整数；列表标记“项目集覆盖”。
  • 由覆盖切回继承时，清空项目集覆盖字段，并实时读取当前服务默认值供后续新工单使用。
  • 不在合同、项目两个层级增加时长字段。

FR-03　工单取值与快照

  • 创建工单时先读取项目集服务覆盖值；覆盖为空时读取服务默认值。
  • 操作人在业务表单中修改后，以修改值保存工单，并将来源标记为 WORK_ORDER。
  • 工单创建成功后，配置层变化不更新工单字段。
  • 详情页显示“预计服务时长 + 来源标签”；修改入口保存后同步刷新。

FR-04　会诊工单

  • 创建会诊工单时不要求填写时长；分诊安排会诊日期、时间和专家时增加必填“预计服务时长”。
  • 详情在“会诊信息”模块展示，保持房间号、状态、链接、视频等现有信息结构。
  • 修改入口位于页面右侧“修改会诊时间”，弹窗内允许调整时长。

FR-05　诊所服务与远程门诊

  • 诊所服务在现有“创建工单”抽屉的申请信息中新增必填“预计服务时长”；远程门诊沿用现有“服务时长”数据与字段能力，并将页面名称统一为“预计服务时长”。
  • 详情均在“申请信息”区域展示；操作按钮统一使用“修改”。
  • 远程门诊结束时间 = 出诊开始时间 + 预计服务时长；开始时间或时长变化后重新计算。

FR-06　绿通

  • 创建申请时不填写预计服务时长。
  • 安排协调结果并录入就诊日期、时间时，增加必填预计服务时长。
  • 详情在“安排资源”区域展示；修改协调结果时允许同步修改。

取值算法

baseMinutes = projectSetService.estimatedDurationMinutes
  ?? service.defaultEstimatedDurationMinutes
baseSource = projectSetService.estimatedDurationMinutes != null
  ? "PROJECT_SET" : "SERVICE_DEFAULT"

if (isCreatingWorkOrder) {
  finalMinutes = submittedMinutes ?? baseMinutes
  source = finalMinutes === baseMinutes ? baseSource : "WORK_ORDER"
} else {
  finalMinutes = submittedMinutes
  source = finalMinutes === workOrder.estimatedServiceDurationMinutes
    ? workOrder.estimatedDurationSource : "WORK_ORDER"
}

workOrder.estimatedServiceDurationMinutes = finalMinutes
workOrder.estimatedDurationSource = source

接口规则

接口对象JSON 字段方向规则
服务defaultEstimatedDurationMinutes读 / 写5—1440 的整数分钟；上线迁移期读取可为空。
项目集服务estimatedDurationMinutes读 / 写NULL 表示继承服务默认值，非空表示项目集覆盖。
工单estimatedServiceDurationMinutes读 / 写适用业务保存时必填；历史数据可为空。
工单estimatedDurationSource只读后端计算并返回，前端不得提交为可信值。
工单estimatedDurationUpdatedBy / estimatedDurationUpdatedAt只读由后端按操作上下文记录。
  • 服务与项目集接口统一返回分钟整数，不返回格式化小时字符串。
  • 工单创建/分诊/协调结果接口接收 estimatedServiceDurationMinutes；适用场景缺失时返回明确业务错误。
  • 后端根据工单关联的项目集与服务解析基础值并校验归属关系，不接受前端传入项目集覆盖值或来源枚举作为可信依据。
  • 工单详情接口返回分钟值、来源枚举、最后修改人和修改时间。
  • 来源枚举由后端按最终值计算，前端不得直接指定或覆盖 estimatedDurationSource。
  • 数据不变量：预计分钟值与来源必须同时为空或同时非空；非适用工单及未迁移历史工单两者均为空。
  • 前端展示统一拼接“分钟”，不得自行转换为“小时”。

迁移策略

  1. 确认远程门诊旧“服务时长”字段、单位及使用接口。
  2. 若旧字段位于统一工单实体且语义一致，则直接复用或重命名；若位于远程门诊子表，则一次性回填统一工单字段。切换后只保留一个写入口，不长期双写。
  3. 其他历史工单保持 NULL，不用当前服务配置回填；详情显示“—”，且不阻断历史工单原有查看和流转。
  4. 上线前完成适用服务的默认值配置；未配置服务进入阻断清单。

08　上线、监控与风险

上线步骤

  1. 数据库字段与接口兼容先行，旧客户端/旧调用不受影响。
  2. 执行远程门诊字段兼容或迁移，并完成全量值比对。
  3. 运营配置适用服务的默认预计服务时长，输出未配置阻断清单。
  4. 开放项目集覆盖配置，再开放四类工单入口。
  5. 上线后一周监控缺失率、异常值、工单调整率与接口错误。

监控指标

  • 适用新工单时长缺失率：目标 0%。
  • 时长非法值写入数：目标 0。
  • 项目集覆盖率与工单人工调整率：用于识别默认配置是否合理，不设硬目标。
  • 远程门诊迁移差异数：目标 0。

主要风险与控制

风险影响控制措施
默认值被理解为患者承诺引发服务预期争议仅后台展示，文案统一“预计”，患者端不展示
配置变化追溯历史排班与统计结果漂移工单保存快照，禁止配置批量回写历史
