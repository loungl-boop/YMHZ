RECONCILIATION
数据可对照

报销不含服务费，退款不计充值。按单卡保留原扣款和实际退款，核对消费净额。

本次修订：工单完成后触发结算

适用会诊与诊所服务的会员卡-扣费、会员卡-权益抵扣。创建工单时仅保存支付信息与费用快照；工单变为已完成时，尤迈服务自动执行扣款，非尤迈服务发起企业微信审批，审批通过后执行扣款。完成前不执行上述动作。自费、项目权益抵扣沿用原流程。

扣款失败不回退工单完成状态，订单保持未支付并通知财务。完成、审批回调、补扣分别防重复；已支付后审批撤销仍先人工核对，暂不重提。

服务费统一可调，支付按实际资产拆分

尤迈默认 0%，非尤迈按服务配置，健康专员可调整本单比例并说明原因。审批仍按服务性质：尤迈直接结算，非尤迈需审批，不受本单是否收费影响。

会员卡扣费扣服务金额加服务费；权益抵扣服务时，服务费从同卡余额扣除。先校验权益与余额，全部满足才整体结算；仅实际现金计入余额消费。

本轮新增：订单垫资信息

是否垫资、垫资人和实际垫资金额归属消费订单，创建时填写、订单详情补录或更正。垫资人默认创建订单的当前账号，代创建可改为实际垫资人，与医助无关联；垫资金额默认服务金额并可修改。两类服务均可登记。报销范围按垫资事实判断，个人统计与选单采用实际垫资金额，同一报销单仅同一垫资人。

3. 整体业务流程

3.1 购卡与充值收款

客户付款或财务发现来款 → 线下认领与核对 → 专员创建订单 → 通知财务 → 财务确认收款 → 原建卡/入卡处理 → 通知订单创建人。

3.2 服务履约与客户结算

服务配置 → 创建工单并保存费用/支付及垫资信息 → 履约并完成工单 → 尤迈执行会员卡结算，非尤迈发起企微审批、通过后结算 → 客户结果告知 → 按实际垫资选单报销 → 线下完成后财务登记，或未付款时整单退回。

工单状态、客户支付状态、企微审批状态、扣款执行结果和报销状态分别记录。创建或提交工单不触发本期会员卡扣款或审批，失败不回退工单已完成；自费和项目权益原流程沿用。

3.3 垫资登记与报销

创建工单或订单补录实际垫资 → 客户订单满足已支付等条件 → 按同一垫资人选单 → 核对实际垫资金额并提交 → 线下核对及付款 → 财务登记已报销；未付款被拒绝时整单退回 → 更正并重新申请。

4. 按系统模块的功能方案

4.1 产品服务：服务性质与服务费

服务性质固定为尤迈/非尤迈，同一服务不能临时切换性质，差异建不同服务。性质不等同会诊/诊所业务类型或会员端展示分类。基础服务维护收费依据，会员展示不重复配置。

尤迈默认服务费比例0%；非尤迈默认跟随系统统一比例或服务自定义比例，支持0%、最多两位小数。统一设置填写说明并记录调整前后比例、原因、人员和时间，影响后续新单默认值，不改旧单快照。跟随服务通过列表筛选查看。

两类服务的本单比例均允许调整，调整时填写原因；性质、默认/实际比例、原因、调整人与计算结果随订单保存，不回写服务配置。服务金额是否可编辑继续由原允许改价开关决定，不影响本单比例调整。

服务费＝服务金额×本单比例，收费合计＝服务金额＋服务费。本地金额按分四舍五入演示；最终舍入、比例上限和存量服务初始化仍待技术/业务核对。审批始终由性质决定：尤迈增加服务费仍不审批，非尤迈免收仍审批。

4.2 订单管理

4.2.1 购卡、充值与收款分工

客户付款后，可由客户告知专员，或财务发现入款后线下询问认领。认领一致后健康专员创建待支付订单，系统提醒财务；财务核对到账再确认已支付，系统提醒订单创建人。所有不一致线下沟通，不新增银行来款认领模块。

确认购卡已支付时创建待激活卡，后续由专员或客户激活；确认充值已支付时本金、赠送及权益进入指定卡并跟随卡状态生效。原支付后资产处理沿用。订单办理在PC，企微移动端只承载提醒，不新增移动办理页。

4.2.2 服务消费订单与办理支付

未支付入口及抽屉名为办理支付，待退款为办理退款；列表待退款直接展示按钮，不包裹单项更多菜单，底部确认/取消沿用。原未支付改价权限继续保留，业务决定是否修改；已支付订单金额不可改，不新增强制重审批。

办理支付表单沿用原字段。本原型未展开原订单金额编辑，填写的应付/实付与当前所选方式应付不一致时给出业务提示，先核对或按原订单金额编辑能力处理；不将研发标注当作办理结果。真实分项联动按原系统核对，不能把原型演示限制解释为生产新增金额锁定。

4.2.3 订单垫资登记与修改

创建工单费用支付及消费订单详情维护是否垫资、垫资人、实际垫资金额，归属消费订单，独立于服务性质和医助。是否垫资为未登记/是/否；未登记不等于未垫资，预填默认值也不等于已经实际付款。

创建时垫资人默认创建订单的当前后台账号，允许代创建填写实际人员；订单补录默认原创建账号。医助改变不影响垫资人。垫资额默认服务金额、不含服务费，可改为实际金额；创建时未手动改额前随服务金额，手改后保留。金额为正数、最多两位小数，有效后台账号必填。

客户未支付也可登记垫资。订单详情及消费订单报销列表/详情可补录更正；保存不改医助、原订单收费、客户支付或卡资产，取消不保存，修改留前后快照、人员和时间。有效报销关联期间不直接改垫资信息；财务退回释放后可更正重申。

4.2.4 取消工单后的退款办理

诊所已支付工单取消后联动消费订单待退款，复用会诊已有退款字段与操作；未支付取消不产生退款。会员卡扣费或会员卡权益抵扣，才进入原会员卡退回能力。财务人工填写实际金额及退款时间，路径显示退回至会员卡；权益退原权益，权益订单现金仅对应实际服务费。退款不计充值，不改变原支付金额，不新增手续费/违约金自动算法，原校验沿用。

自费及其他非会员卡支付的退款先联系财务线下核对，原型不执行会员卡余额或权益退回，也不擅自标记已退款；不新增未经核验的现金渠道退款能力。已进入报销或已报销后的客户退款、同单多次退款、部分权益退回和有效期恢复仍需另行细化。

历史已知一单通过补充值处理退款，由技术核对原消费、补充值及实际恢复资产，修正归属/关联及统计并留依据，不预设删单或重复退款。

4.3 工作台与工单管理

会诊/诊所创建工单保留申请信息、患者病历、费用支付三步；服务说明与患者附件沿用，不新增必填上传要求。提交只保存订单快照及支付方式/会员卡。工单变为已完成时，会员卡扣费与会员卡权益抵扣才按服务性质触发处理。

场景处理
尤迈服务无需内部审批，工单已完成时自动执行会员卡扣费或权益及服务费结算。
非尤迈服务工单已完成时创建企微审批单，节点及顺序由企微配置；仅当前有效申请已通过才执行结算。
会员卡扣费从同卡余额扣服务金额加服务费。
会员卡权益抵扣服务消耗原配置权益，服务费从同卡余额扣除。先整体检查权益与余额，任一不足不动两类资产。
扣款失败保持工单已完成和订单未支付，保留余额不足/权益不足/系统失败等具体原因，企微通知财务。
失败后的办理支付充值或系统恢复后，财务复用后台办理入口补扣，或核实客户自费；不新增专员重试，不因充值自动重试全部订单。

实际整体成功才已支付，重复完成、审批回调及补扣不得重复扣资产。结果未知先核实，不能盲目重试。客户只接收结果告知，异议线下联系专员；不再有客户或专员代客确认环节。

4.3.1 企微审批及重新提交

已通过执行扣款；已驳回、已撤销、通过后撤销属于失败，未支付且满足原条件时允许确认后重新提交新申请，保留历次记录。其他过程状态不提供审批重提操作。旧申请或重复结果不能覆盖新申请或再次成功结算。

审批已通过而扣款失败，沿财务原办理入口处理，不重新发起审批。已支付后审批撤销先人工核对、暂不重提，也不自动退款。

4.4 财务管理

4.4.1 消费订单报销：个人总览与选单

报销范围按已登记垫资和实际垫资人决定，不按尤迈/非尤迈限制。报销金额取实际垫资金额，不取服务售价，不含服务费。客户消费订单必须已支付，人员金额有效，无其他有效报销占用，且不在取消、退款或审批撤销待人工核对等异常中，才可申请。

个人总览与筛选

默认实际垫资人为当前账号，允许在原权限范围切换其他人或全部。主视图为已登记垫资，次级全部消费订单查询用于核对未登记/未垫资和补录；全部筛选不扩大数据权限。

五项总览为累计垫资、尚未报销、可申请、正在报销、已报销，均以实际垫资金额为主、笔数为辅。尚未报销包含未申请和报销中，可申请为其中子集，五项不能直接相加。客户未支付或退款异常仍保留实际垫资记录，只禁申请，不推定垫款已归还。总览按人员及公共查询条件，标签/快捷状态不重算总览。

状态标签全部垫资/未申请/报销中/已报销；点击可申请金额卡快捷过滤，全部消费订单还可区分未登记、未垫资。筛选、标签或范围切换及修改后清空选择，避免隐藏选单。

同人合单与申请快照

同一报销单只能包含同一实际垫资人的订单，可跨客户和会诊/诊所业务合并，也可单笔申请；有权限者可代提交，提交人与垫资人分开记录。一笔订单按实际垫资金额一次性申请，不拆成多次部分报销；整单完成后一次登记，不做合单内分批确认。

选单显示笔数及实际金额合计，确认页按订单逐笔核对。金额有误先取消并更正订单，不维护第二套申请金额。提交重新校验资格、人员、占用及确认快照；若金额/归属变化需重新核对。原申请保存明细和金额快照，后续订单变化不静默改写。

4.4.2 俱乐部垫资报销：已提交单据管理

俱乐部垫资报销仅管理已提交单据；默认提交人当前账号，实际垫资人全部，支持两条件组合查询及其他人/全部，重置恢复默认。后台账号ID关联归属，历史账号保留查询，沿用数据权限。

创建报销单为待报销，关联订单为报销中；财务线下整单完成后登记已报销，关联订单同步已报销。客户支付和报销结果分别表示，客户扣款不自动完成专员报销。

4.4.3 线下未付款的财务整单退回

财务可退回待报销且线下尚未实际付款的单据，填写原因并确认未付款，只做整单退回。原报销单状态已退回，保留原申请明细/金额及退回原因、人员和时间；原订单解除有效占用并记历史，恢复未申请，按当前条件重新判定资格，更正后新建申请。

金额由正在报销回到未申请，尚未报销总额不变；符合条件部分回到可申请。旧单不能再登记已报销或重复退回，重复/过期操作不能释放新单关联；取消不改状态。线下实际已付款（含尚未登记）不采用普通退回，财务据实确认，平台不宣称自动识别线下付款。

4.4.4 报销单附件打印

详情提供打印预览及浏览器打印/保存PDF入口。A4纵向附件包含单号、当前状态、提交人、垫资人、创建时间、订单数量、业务类型及申请明细/合计；取申请快照，已退回明确标记并附退回记录。

仅输出所选单据，不打印后台导航、操作、标注或方案正文；多页重复表头。打印不改变报销/支付状态或资产，不代表线下付款完成。最终设备输出及PDF分页仍需使用环境核验。

4.5 会员中心：单卡账户与明细

以单张会员卡展示，完整卡号唯一关联实际支付卡；姓名及尾四位仅展示。累计本金/赠送及合计统计实际购卡充值入卡，不含消费退款。消费分服务金额扣款、服务费扣款，另列实际退款和净消费；待退款不提前冲减，原扣款不因已退款而消失。

权益本身不折现；权益抵扣订单中，从同卡余额实际扣除的服务费仍计入服务费消费。自费未扣本卡不计本卡消费。实际消费净额为服务扣款加服务费扣款减实际退款，账户余额沿用原权威结果。

购卡充值与消费分明细，原扣款/退款分行关联；按当前卡及筛选导出全部匹配记录。原型CSV用于核对范围，正式格式及大数据导出待技术评审；财务暂无固定模板。

4.6 工作台：交班表

按当日会诊时间或服务时间展示，原列及排序沿用。诊所补齐消费类型、备注、客户来源；消费类型由支付方式生成，不是人工填写项。

  • 自费/项目权益抵扣：支付方式（项目集备注名）。
  • 会员卡扣费/会员卡权益抵扣：支付方式（实际支付卡主卡人姓名-卡号后四位）。
  • 备注：工单填写优先，未填取项目名称。
  • 客户来源：工单填写优先，未填取临床医生所在医院。

仅调整原定时任务填充规则，执行范围、时机、频率及历史处理保持现状，不增加实时取数、历史回刷或冻结。空项目备注建议只显示支付方式，卡主信息缺失展示继续核对，不新增建单必填。

4.7 消息中心：内部通知

技术固定事件、触发条件、内容/变量及企业微信渠道，业务仅维护后台接收账号。后台账号统一维护企微UserID，不在通知配置重复录入。不提供事件新增、表达式、内容编辑、渠道切换、启停或手工发送。

预置购卡建单、充值建单、收款确认成功及自动扣款失败四类内部通知。财务类通知可多选指定账号，收款成功自动关联订单创建人；有效接收账号校验绑定及状态。客户消费结果继续沿用旧系统配置，不在新模块体现。

记录事件、业务单、实际接收账号、当次UserID/内容、时间及结果原因，历史不随配置回写。渠道已受理不等于送达/已读，通知失败不回滚成功交易。真实企业微信能力、PC办理链接、失败查询与重试机制待联调，不添加未确认的额外通知范围。

5. 共享规则与异常处理

5.1 权限与人员归属

同一页面按原按钮权限及数据范围操作。消费订单报销默认当前实际垫资人，已提交报销单默认当前提交人；订单创建人、实际垫资人、医助及报销提交人分别表达，允许有权限者代提交，不因筛选全部扩大查看权限。

5.2 金额与历史快照

客户收费、实际现金扣款、权益消耗、实际垫资及报销申请金额分别记录。报销取实际垫资金额，不含服务费；申请与打印按提交时快照，服务配置及后续订单变化不静默改写历史金额。

5.3 状态与异常衔接

工单履约、审批、客户支付、扣款执行与报销结果相互独立。扣款失败不回退工单完成；财务未付款整单退回只释放原报销占用，不代表客户退款或专员已收回垫款；已付款不采用普通退回。

5.4 资产一致性与防重复

会员卡权益及现金服务费整体校验执行，失败不部分动资产，重复完成/回调/补扣不重复结算。退款按原支付路径区分，非会员卡退款不入会员卡；通知失败不回滚已成功交易。实际事务、结果未知的核实与接口幂等仍需联调。

6. 待细化与联调边界

  • 专员主动撤回已有需求方向，当前只实现财务退回；撤回资格、状态和操作细节仍需确认后补原型，不当作已具备。
  • 已报销后客户退款或实际垫款退回/冲销，与未付款前普通退回分别设计；不自动追回、重算或开放已报销普通退回。
  • 公司成本、利润算法未统一，不将服务费等同利润，不把未知成本展示为0。
  • 金额舍入、比例上限、存量服务性质初始化、真实权限字段、审批及跨资产事务/幂等、数据导出格式和历史一单修正仍需技术核验。
  • 原功能未完整重画的部分沿用原系统；本地合成原型不接真实账户或消息。打印最终输出仍待使用环境确认。
