MEDICAL ASSISTANT QUEUE VIEW

一次选定时段，列表内连续切换全部状态

面向医助角色，为今日预约增加上午/下午切换，并将三个分散状态列表统一为可连续浏览的队列视图。

角色：医助范围：当前活动／日期／专家交付：产品方案＋交互原型＋PRD
01 / REVIEW SUMMARY

评审结论

保留原入口和卡片信息，在不增加新的业务状态前提下补齐两个维度的切换。

入口页补齐时段

“今日预约”旁增加上午/下午分段控件，数字、就诊中和候诊中均跟随所选时段刷新。

列表页补齐状态

从任一数字进入后，可直接切换待叫号、待就诊、已完成，同时仍可切换上午/下午。

上下文持续保留

进入列表继承入口页时段；切状态保留时段，切时段保留状态；返回入口仍停留在原时段。

术语说明：入口截图使用“已完成”，现有详情截图标题使用“已就诊”。本方案前端统一展示“已完成”；是否映射单一后台状态或状态集合，须在开发前结合现有接口确认，本方案不擅自改变状态机。

02 / PROBLEM & OUTCOME

解决什么问题

现状

医助一次只能查看一个半天；进入数字详情后只能查看被点击状态，跨状态需要返回首页。

目标体验

上午/下午和状态成为两个独立筛选维度，任意组合都可在同一浏览链路内到达。

成功判断

任何切换均不混淆活动、日期或专家；数量与列表一致；返回路径不丢失选择。

03 / SCOPE

交付范围与边界

本次纳入

  • 医助首页上午/下午切换。
  • 三个统计数字及首页队列随时段刷新。
  • 数字入口继承时段和目标状态。
  • 统一列表内上午/下午与三状态切换。
  • 各状态沿用现有卡片字段和搜索能力。
  • 加载、空态、刷新、返回和状态变化处理。

本次不纳入

  • 不新增或重定义患者主状态。
  • 不改造取号、叫号、签到、接诊及完成动作。
  • 不改变医助的数据权限和专家绑定关系。
  • 不增加跨日期、跨活动或跨专家查看。
  • 不增加患者搜索范围或导出能力。
  • 不承诺新的实时刷新频率或性能 SLA。
04 / FLOW

核心流程

1进入工作台按活动配置的切换点定位初始半天。
2选择时段上午/下午任选，刷新数字与队列。
3点击数字带入所选时段和目标状态。
4浏览列表沿用对应状态的现有卡片。
5连续切换时段和状态可独立组合。
6返回入口恢复离开前的时段上下文。

双维度筛选模型

06 / INTERACTION RULES

关键交互规则

时段不等于接诊开关

切换只改变当前数据上下文，不自动开启、关闭或重置接诊状态。

维度互不覆盖

切换上午/下午不回到默认状态；切换状态不跳回系统默认半天。

数量必须同源

页签数量、首页数字与当前筛选列表使用同一口径，避免“数字能点、列表对不上”。

现有能力不扩张

搜索只在现有已完成列表继续展示，其他状态不因统一容器而新增搜索。

07 / OPEN POINT

上线前唯一待确认项

“已完成”与“已就诊”的接口映射需确认首页“已完成”当前统计口径、现有“已就诊列表”查询条件，以及 ADR-006 中“意见提交后从已就诊变为已完成”的状态流转。确认后只调整映射配置，不改变本方案的页面交互。

01 / SUMMARY

概要说明

当前医助首页只能呈现单一半天数据，三个统计数字进入后又形成彼此隔离的状态详情。本版本增加时段切换，并把三个详情整合为同一列表容器：时段与状态互为独立筛选条件，用户可在任意组合间快速切换。

核心边界本次是查看路径与筛选上下文改造，不新增患者主状态，不改变中意报名与原始预约边界，也不扩张医助对其他活动、日期或专家患者的访问范围。
02 / GOALS

目标与成功标准

业务目标

  • 医助可快速了解上午和下午的队列分布。
  • 减少跨状态查看时的返回与重复进入。
  • 保持数字、页签人数和列表明细口径一致。

功能成功标准

  • 入口页可切换上午/下午，相关区域同步更新。
  • 点击数字后准确继承时段与状态。
  • 列表内支持 2×3 的全部筛选组合。
  • 返回首页时恢复原时段，不出现上下文跳变。

切换耗时、列表加载耗时等数值先通过试点建立基线，正式目标在技术评审后确定，不在本方案中承诺 SLA。

05 / BUSINESS RULES

业务与状态规则

初始时段

  1. 进入医助工作台时，按系统当前时间与活动配置的上午/下午切换点定位初始时段，不固定使用自然 12:00。
  2. 切换时段只改变数据上下文，不自动开启、关闭或重置接诊状态。
  3. 用户可查看另一时段；其中记录是否可操作继续沿用现有业务规则，本方案不新增解锁条件。

筛选继承

  1. 点击首页任一统计数字，列表继承首页当前时段，并选中被点击状态。
  2. 列表切换状态时保留当前时段；切换时段时保留当前状态。
  3. 从列表返回首页时，首页恢复离开前所选时段。
  4. 切换后列表滚动回顶部；搜索词仅属于已完成列表，离开已完成时不参与其他状态查询。

数量与状态变化

  1. 首页数字、列表页签数字和当前列表明细必须使用同一查询口径。
  2. 列表仅返回当前活动、日期、专家/诊室、时段和状态下，医助有权查看的记录。
  3. 若记录在浏览期间发生状态迁移，按现有实时刷新机制更新；没有实时机制时，在切换筛选、返回页面或用户主动刷新时重新获取。
  4. 取消、过号等其他状态不合并进三个页签，继续沿用现有入口和处理规则。

已完成术语

前端页签与标题统一使用“已完成”。其数据是否等于后台“已完成”，或需兼容当前“已就诊列表”的查询口径，列为开发前接口确认项。确认结果不得导致首页数字与列表明细不一致。

08 / SECURITY & AUDIT

安全、隐私与审计

  • 时段和状态参数不能扩大医助既有数据范围，服务端必须按活动、日期、专家/诊室和角色复核权限。
  • 列表继续使用当前脱敏展示；不因统一列表返回其他状态不需要的健康资料。
  • 中意和企业客户不会因本功能获得个体患者查看权限。
  • 记录页面进入、时段切换、状态切换、搜索和加载失败，用于质量分析；不记录搜索框中的完整证件号明文。
  • 若现有状态映射发生配置变更，应记录变更人、时间、旧值和新值。
09 / NON-FUNCTIONAL

非功能要求

类别要求
一致性统计数字、页签人数和列表明细使用同一筛选上下文与状态映射。
可用性上午/下午与三状态控件在常用手机宽度下均完整可见；触控区域满足移动端操作。
容错切换失败不清空当前可用数据，不把失败后的空响应误展示为“暂无患者”。
性能先采集切换和列表加载基线；骨架屏或局部加载不得阻塞返回操作。
兼容性支持当前医助移动端统一支持的浏览器或应用容器。
可访问性选中态同时使用文字、色彩和底部指示，不只依赖颜色。
