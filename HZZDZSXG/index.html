中性字段展示改造产品方案

针对部分医院对专家院外执业和出诊表述的严格要求，将平台外显的“会诊、诊疗”相关字段替换为更中性的业务文案。本期只改展示，不改数据、流程与权限。

版本 v1.2 状态：可进入技术评审 基线日期：2026-08-13 共 20 个字段点
一句话方案

通过“统一中性文案 + 项目模板路由 + 新旧内容边界”的轻量改造，降低敏感表述风险，同时保证现有业务链路零迁移、低回归。

05 / PRINCIPLES

方案原则

01

外显中性化

对用户可见的“会诊、诊疗”敏感表述按清单逐项替换，不扩展到非目标词汇。

02

底层稳定

避免改动字段键和业务模型，从根源上控制联调、迁移与兼容成本。

03

模板可追溯

明确 AZ、通用和中意三类模板路由，测试时可按项目定位最终输出。

04

版本可回滚

文案映射集中维护，发布时同步刷新缓存；发生异常可回退上一版本资源。

06 / BOUNDARY

范围与非目标

本期纳入

  • 后台生成的专家在线填写链接页面与分享话术
  • AZ模板原有2个项目集，新增4个项目集，最终适用范围为6个项目集；覆盖通用模板的新生成图片
  • 在线病历页、待分诊分享话术和已分诊分享话术
  • 缓存、静态资源与多实例发布一致性验证

本期不做

  • 小程序字段配置及医生端任何页面修改
  • 中意模板修改、历史图片重生成或历史消息回刷
  • 数据库/API/状态/权限/埋点事件名调整
  • 二期的项目级字段配置后台与运营操作入口

07 / COMPATIBILITY

新旧内容兼容策略

“动态页面”和“已固化内容”采用不同处理边界。

发布前已发送消息

消息正文不追溯修改；其中仍有效的链接打开后加载当前页面文案。

发布前生成图片

作为静态产物保留原样，不批量重生成，不做历史数据处理。

发布后动态页面

统一展示目标文案，包含旧有效链接再次打开的场景。

发布后新内容

新分享消息和新生成图片均使用目标文案及对应模板路由。

08 / PROTOTYPE DECISION

本次不提供原型页面

结论：合理

本次需求没有新增页面、入口、控件、布局、交互流程或状态反馈，仅替换既有位置的可见文字。单独制作原型会重复表达字段矩阵，且容易形成第二套口径。因此以“页面/模板位置 + 现网文案 + 目标文案 + 实现规则 + 验收场景”作为唯一开发基线。若二期建设项目级字段配置后台，再补充配置页原型、权限和生效机制。

1. 执行摘要

1.1 背景与问题

部分合作医院对专家院外执业、出诊及相关宣传表述管理较为严格。现有远程会诊服务平台在专家填写链接、分享话术、在线病历和生成图片中，存在“会诊、诊疗”等直接外显字段，可能给项目落地和院方沟通带来额外解释成本。

1.2 目标

  • 将本期清单内的外显字段统一调整为中性表述，满足当前项目的展示要求。
  • 维持原业务流程、数据结构、权限和接口兼容性，避免引入迁移成本。
  • 建立字段 ID、模板路由和新旧内容边界，供研发实现和测试逐项验收。

1.3 成功标准

维度成功口径
字段准确性20 个字段点目标文案匹配率 100%，无错字、漏改、误改
业务稳定性提交、分享、图片生成、链接校验和在线病历链路无回归
不改范围小程序、医生端、中意模板、历史静态产物保持既定边界
技术兼容不新增表/字段，不修改接口键、状态值、权限与埋点事件名
发布一致性多实例、模板缓存和静态资源不存在新旧文案混用

2.2 用户故事

US-01 专家填写：作为受邀专家，我希望页面使用清晰中性的“意见、专家、时间”等字段，以便无需学习新流程即可完成填写和提交。
US-02 医助分享：作为医助，我希望生成的引导话术和分享内容统一使用目标文案，以便在院方沟通时保持口径一致。
US-03 项目输出：作为项目运营，我希望不同项目准确命中对应图片模板，既落实当前改造，又不影响明确无需修改的中意模板。
US-04 历史兼容：作为系统维护人员，我希望历史静态内容无需重生成，旧有效链接仍可正常打开并加载当前页面文案，以控制上线风险。

2.3 功能需求

  1. 在线填写意见：按 O-01～O-07、O-09 修改分享话术、页面字段、输入提示和提交成功提示。
  2. 生成图片：AZ模板按 G-01 同时修改“诊疗意见→意见”和适用项目集范围：原有2个项目集，新增4个项目集，最终适用范围为6个项目集。通用模板按 G-02～G-07 修改；中意模板保持不变。
  3. 在线病历：按 M-01～M-05 修改待分诊/已分诊分享话术、页面标题与页面内容字段。
  4. 系统边界：小程序继续使用现有系统配置展示名，医生端不修改。
完整字段逐项映射位于本文件的“开发对照”页。字段 ID、位置、现网文案和目标文案为强制验收口径。

2.5 交互与视觉要求

页面布局、字段顺序、字号、颜色、控件、校验提示、按钮、链接、提交反馈和响应式规则均保持现状。目标文案较长时，应复用现有自动换行能力，不得因替换造成截断、遮挡、图片溢出或换行异常。

2.6 非目标

本期不建设配置管理页面，不允许项目人员自行维护字段；不调整小程序和医生端；不回刷历史消息，不重生成历史图片；不对“会诊、诊疗”执行无差别全局替换。

3. AI 需求

本需求不包含 AI 能力，不涉及模型调用、提示词、知识库、自动生成、内容审核模型或 AI 指标。所有目标文案均为产品确认后的确定性配置。

4. 技术规格

4.1 建议实现方式

在现有页面资源、服务端模板或配置层集中维护展示文案。以“模块/页面 + 模板类型 + 项目路由”为解析条件，输出目标文案。不得因中文展示名称变化而重命名接口字段、数据库列、状态枚举或埋点事件。

层级要求备注
前端页面替换页面标题、字段标签、placeholder和成功提示保留 DOM 结构、校验和行为
分享消息新生成的引导/分享内容使用目标文案历史已发送正文不回刷
服务端图片按项目与模板路由输出目标字段验证换行、字体宽度和图片边界
配置/缓存发布后主动刷新各层缓存验证多实例一致性

4.2 数据与接口

  • 不新增或修改数据库表、字段、索引和存量数据。
  • 不修改 API 地址、请求/响应字段名、字段类型与业务状态值。
  • 不修改表单提交内容、分享链接参数、鉴权方式与链接失效机制。
  • 如现有文案由配置中心提供，可更新展示值，但配置键保持稳定。

4.3 权限、安全与隐私

沿用现有登录、链接访问、患者信息脱敏和数据权限策略。本次文案改造不扩大任何角色的数据可见范围。发布检查需确认异常日志、分享内容和图片输出未新增敏感患者信息。

4.4 历史与兼容

对象处理策略
历史图片保持原样，不批量重生成
已发送消息正文保持原样，不回刷第三方会话内容
历史有效链接链接参数和权限不变；打开后动态页面展示当前版本文案
已失效链接继续执行原失效逻辑，相关提示按 O-09 验收

4.5 非功能要求

  • 性能：文案解析不得新增远程调用；页面加载和图片生成耗时不应有可感知增加。
  • 可维护性：同一目标文案避免在多处散落硬编码；重复免责声明建议共享常量或同源配置。
  • 可观测性：沿用现有错误日志和成功率监控；发布期间关注链接打开、提交和图片生成异常。
  • 可回滚性：应用、模板和配置版本可整体回退，并在回退后刷新缓存。

6. 验收、发布与回滚

6.1 验收条件

  • “开发对照”页 20 个字段点逐项验收通过。
  • TC-01～TC-12 全部通过，无阻断或高优缺陷。
  • 产品确认目标文案，研发确认无数据与接口变更，测试确认模板与历史边界。
  • 图片产物经过实图检查，页面在主流桌面与移动浏览器下无展示异常。

6.2 发布步骤

  1. 在测试环境完成字段矩阵和模板路由全量验收。
  2. 确认配置、模板、静态资源和应用服务的发布顺序及缓存刷新方式。
  3. 生产发布后执行核心冒烟：在线填写、提交成功、分享、三类图片模板、在线病历。
  4. 观察现有错误日志和关键链路指标；确认多实例展示一致后结束发布窗口。

6.3 回滚策略

如出现页面不可用、模板排版异常、路由误命中或大面积新旧文案混用，整体回退至上一版本应用/模板/配置，刷新全部相关缓存，再执行核心冒烟。由于本期无数据迁移，回滚不涉及数据恢复。

6.4 原型结论

本期不提供原型。原因是需求不改变页面结构与交互，制作原型不能增加实现信息，反而可能形成独立口径。若二期进入项目级配置功能，再针对配置页、角色权限、预览与生效流程补充原型。
