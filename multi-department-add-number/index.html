QUEUE OPERATIONS / MULTI-DEPARTMENT ADD-ON

患者信息只录入一次，一次完成多科室加号

在现有取号员首页“加号”入口内升级填写流程：将患者身份与联系信息作为共享主体，将科室、日期和上午/下午作为可重复的就诊项目，批量提交、按科室返回结果。

影响端：取号员手机端业务域：SYS-QUEUE时段：上午 / 下午版本：2026-10-08 修订
01 / REVIEW SUMMARY

评审结论

本版本只改造现场取号员加号流程，不改变中意的报名与原始预约责任。

交付内容多科室就诊项目、批量确认、逐项结果与失败重试。
不纳入范围患者自助报名/加号、具体时刻、自动跨科路线排程。
影响端仅取号员手机端；现有首页入口和其他角色工作台不变。
状态影响不新增患者主状态；新增加号项目结果口径。
业务数据新增提交批次、批次内顺序、项目结果与失败原因。
权限控制沿用取号员加号权限；科室是否可选及余量完全遵循后台配置。
历史数据不迁移、不回填；存量单科室加号记录保持原样。
兼容策略单科室是批量流程的特例；无需保留两套页面。
02 / PROBLEM & OUTCOME

解决什么问题

将加号动作从“重复填写患者表单”转为“为同一患者维护多个就诊项目”。

现状

每次操作只能选择一个科室，多科室需重复输入身份证、姓名和联系方式。

目标体验

患者信息只核对一次，取号员连续添加科室，一次确认后按项目获得结果。

成功判断

同一批次的患者数据唯一且各科室记录正确；部分失败不造成成功项重复创建。

功能上线后先在试点活动记录单人多科室操作时长、重复录入次数、部分失败率和误绑率，建立基线后再评审数值目标，本方案不预先承诺 SLA。

03 / SCOPE

交付范围与边界

交付范围

  • 首页沿用现有“加号”入口。
  • 患者信息录入/证件识别与人工核对。
  • 1—4 个科室就诊项目的添加、删除和排序。
  • 每项独立选择活动日期与上午/下午。
  • 容量状态、重复科室与同半天冲突提示。
  • 批量确认、逐项结果和失败项重试。

不纳入范围

  • 不建设患者自助报名或加号入口。
  • 不替代中意的原始预约和报名数据。
  • 不选择具体就诊时刻，不计算跨科路线。
  • 不改造取号、叫号、签到和专家工作台。
  • 不使用 AI 进行科室推荐或容量决策。
  • 不因加号压缩已预约患者的咨询时间。
04 / FLOW

核心流程

1进入加号取号员从现有首页入口进入。
2核对患者录入或识别证件，人工确认姓名和电话。
3添加科室逐项选择科室、日期和上午/下午。
4校验与提示校验后台配置、剩余数量、重复科室和同半天冲突。
5汇总确认一次查看患者与全部就诊项目。
6逐项返回成功或未成功，失败项可重试。
05 / PRINCIPLES

设计原则

患者信息唯一

批次内只维护一份患者信息，科室项目不再复制。

科室项目独立

每个科室拥有自己的日期、半天、容量状态和结果。

部分成功不回滚

有效科室已创建即保留，失败项单独调整，防止重复号。

后台配置唯一

不允许加号或剩余数量为 0 的科室不可选择，前端不额外推导审批状态。

PRODUCT REQUIREMENTS DOCUMENT

多科室批量加号 PRD

面向现场取号员，在不重复录入患者信息的前提下，完成多科室加号和逐项结果处理。

状态：定稿决策：ADR-007原型：已覆盖
01 / SUMMARY

概要说明

现有加号流程以单科室为单次操作对象。本版本将表单调整为“患者主体＋就诊项目集合”，一次最多添加 4 个科室。前端一次确认，系统以同一批次发起多条科室加号记录，并逐项返回结果。科室能否选择及剩余数量以后台配置为准。

核心业务边界这是尤迈现场执行工具，不是新的患者报名入口。中意继续维护报名和原始预约；加号不得以压缩已预约患者的咨询时间为代价。
02 / GOALS

目标与成功标准

业务目标

  • 同一患者多科室加号不重复录入身份信息。
  • 科室、日期、半天和容量结果可独立校验。
  • 部分失败可快速修正，不重复创建成功项。

功能成功标准

  • 一份患者信息可关联 1—4 条科室项目。
  • 同一科室不能在同一批次重复提交。
  • 科室列表完整展示已选择、有余量、余量为 0、不允许加号四类状态。
  • 成功、未成功的数量和明细一致；重试时只提交失败项。

效率、失败率和误绑率先通过试点活动建立基线，数值目标在基线评审后另行形成，不在本 PRD 中作出 SLA 承诺。

05 / BUSINESS RULES

业务与状态规则

患者与批次

  1. 一次提交只对应一名患者，患者姓名、身份证号和联系电话必填。
  2. 证件识别只填充信息，取号员必须人工核对；默认不保存证件图片。
  3. 点击“确认提交”时产生唯一批次。连续点击、页面重试或网络超时不得生成重复科室记录。

科室配置与列表状态

  1. 后台为每个活动科室配置“允许加号/不允许加号”；允许加号时同时配置允许数量，前端显示实时剩余数量。
  2. 当前批次已选择的科室显示“已选择”，在其他项目中禁用；未选择且余量大于 0 时显示“未选择 · 剩余 N 个”并可选。
  3. 未选择且余量为 0 时显示“未选择 · 剩余 0 个”并禁用；后台配置为不允许加号时显示“不允许加号”并禁用。
  4. 单次至少 1 个、最多 4 个科室；每个科室独立选择活动日期和“上午/下午”，不选择具体时刻。
  5. 日期来源于当前活动及科室排班，按时间升序横向排列；视口严格显示 3 个完整日期，第 4 个及以后仅通过左右滑动查看。前三天显示“今天/明天/后天”，第 4 天起显示“周几＋月日”。
  6. 同日同半天选择多个科室时显示冲突提示，但不阻断提交；确认弹层再次告知。

部分成功

各科室以独立项目完成最终校验，允许一个批次同时存在成功和失败。成功项保持已创建状态；“调整未成功科室”只带回失败项并清空原半天，重试作为新次数记录，但不重复创建已成功项。

08 / SECURITY & AUDIT

安全、隐私与审计

  • 只有具备当前活动取号员权限的账号可使用加号功能。
  • 身份与联系信息按最少必要原则处理；证件图片默认不保存，识别结果由取号员复核。
  • 记录进入页面、识别/修改患者信息、提交批次、各项结果、失败重试，以及后台是否允许加号和允许数量的配置变更。
